# SMA++

**Транспайлер одного DSL в 13 языков программирования.**

Пишешь один `.sma` файл — получаешь код на C, C++, Rust, Go, Java, C#, Kotlin, Python, JavaScript, Bash, HTML, ASM ARM и ASM x86.

## Что это

SMA++ — компактный DSL с автоматическим управлением памятью и оптимизациями. Один источник → 13 исполняемых версий. Код на выходе **идентичен ручному** для каждого языка.

## Быстрый старт

```
all
s_Hello, World!
```

```bash
python3 cma7.py hello.sma hello --run
```

## Синтаксис

### Токены

| Токен | Что | Пример |
|---|---|---|
| `s_` | print | `s_hello world` |
| `e_` | if | `e_x>3` |
| `t` | else | `t` |
| `g_` | while | `g_x<10` |
| `d_` | for | `d_i(0,10)` |
| `q_` | указатель | `q_p=&x` |
| `n_` | sizeof | `n_x` |
| `m_` | struct | `m_Point=px,py` |
| `c_` | class | `c_Point` |
| `h_` | return | `h_0` |
| `z` | break | `z` |
| `v` | continue | `v` |

### Разделители

- `_` — между токеном и телом (`s_hello`)
- `;` — между блоками (`x=5;y=10`)
- `\n` — то же, что `;`
- `:` — открыть блок (опционально)
- `}` — закрыть блок

### Подстановки

```
x=5
s_x = {x}              → x = 5

arr{10}
arr{0}=100
s_arr0 = {arr{0}}      → arr0 = 100
```

### Отступы

Как в Python — закрывают блок автоматически:

```
e_x>3
  s_больше
t
  s_меньше
```

### Комментарии

- `//` — однострочный
- `√` — однострочный (юникод)
- `|* ... *|` — блочный

## Примеры

### Hello, World

```
all
s_Hello, World!
```

### Fibonacci

```
all
n=30
a=0
b=1
i=0
g_i<n
  t=a+b
  a=b
  b=t
  i=i+1
s_fib({n}) = {a}
```

### Массив + цикл

```
all
arr{10}
arr{0}=100
arr{9}=900
sum=0
d_i(0,10)
  sum=sum+i
s_sum = {sum}
```

### Класс

```
all
c_Point
  px=0
  py=0
  set_xy(a,b)
    self.px = a
    self.py = b
  get_x()
    h_self.px

p = Point()
p.set_xy(7, 8)
r = p.get_x()
s_px = {r}
```

## Target (первая строка файла)

| Первая строка | Что генерится |
|---|---|
| `C` | только C |
| `C++` | только C++ |
| `Rust` | только Rust |
| `Python` | только Python |
| `all` | все 13 языков |
| `C,Rust,Go` | выбранные через запятую |
| *(нет target)* | режим интерпретатора |

## CLI

```bash
python3 cma7.py file.sma out                  # только генерация
python3 cma7.py file.sma out --run            # генерация + сборка + запуск (с PGO)
python3 cma7.py file.sma out --run --no-pgo   # без PGO
```

## Флаги компиляторов

**C / C++:**
```
-O3 -march=native -flto -ffast-math -funroll-loops
```

**Rust:**
```
-C opt-level=3 -C target-cpu=native -C lto=fat -C codegen-units=1
```

**PGO** (по умолчанию) — C, C++, Rust:
- C/C++: `-fprofile-generate` → запуск → `llvm-profdata merge` → `-fprofile-use`
- Rust: `-C profile-generate` → запуск → `-C profile-use=default.profdata`

## Автоматическое управление памятью

**Для C / C++ / Rust** — компилятор ставит `malloc`/`free` (`Vec` для Rust) сам. Пользователь пишет только `arr{5}`.

```c
// SMA++ → C
long* arr = (long*)malloc(5 * sizeof(long));
// работа
free(arr);  // компилятор добавил
```

**Для Go / Java / C# / Kt / Py / JS** — используется встроенный GC, ничего не трогаем.

## Гибридная память (C/C++/Rust)

| Размер массива | Стратегия |
|---|---|
| ≤ 64 элементов | стек (`long arr[64]`) |
| 65–4096 | `malloc` |
| > 4096 | `mmap` (страницы) |

Компилятор выбирает автоматически.

## Производительность

**SMA++ → C = C** (идентичный код).
**SMA++ → Rust = Rust** (идентичный код).
**SMA++ → Go = Go** (идентичный код).

При одинаковых флагах — скорость 1-в-1 с ручными языками.

Бенчмарк `sum += i*i` для N=10^7, 50 запусков:

| Язык | SMA++ | Ручной | Разница |
|---|---|---|---|
| C | 0.301s | 0.300s | 0% |
| Rust | 0.298s | 0.317s | −6% (шум) |

SMA++ не быстрее и не медленнее. Clang/rustc делают всю работу.

## Валидаторы

- Границы массивов (`arr{5}` + `arr{10}=x` → ошибка)
- `use-after-free`
- `double-free`
- Утечки памяти
- Типы (`str + int`)
- Арность методов (`add(5)` когда `add(a,b)`)
- Деление на 0
- Строгий компилятор (отклоняет медленное)

## Sandbox

Программа запускается в изолированном окружении. Ловит:
- `SIGSEGV` (segfault)
- `SIGABRT` (abort)
- Timeout (> 5 сек)

## Самопроверка

После генерации C/C++/Rust — синтаксическая проверка (`clang -fsyntax-only`, `rustc --emit=metadata`). Если генератор сломался — сообщение.

## Требования

- **Python 3.10+**
- Компиляторы (опционально, для `--run`):
  - `clang`, `clang++` (C, C++)
  - `rustc` (Rust)
  - `go` (Go)
  - `javac`, `java` (Java)
  - `mcs` или `csc` (C#)
  - `kotlinc` (Kotlin)
  - `node` (JS)
  - `bash` (Sh)
  - `llvm-profdata` (для PGO)

## Структура проекта

```
cma7.py              — точка входа
sma/
  lex.py             — парсер + валидаторы + оптимизации
  gen_core.py        — генераторы: C, C++, Rust, Py, Sh, JS
  gen_adv.py         — генераторы: Java, C#, Go, Kt, HTML, ASM
  run.py             — интерпретатор
```

## Уникальные фичи

- **Один источник → 13 языков**
- **Автоматическое управление памятью** для C/C++/Rust
- **Авто-типы** — не пишешь `int64`, `long` (выводятся)
- **Код идентичен ручному** — не «улучшенный», не «упрощённый», а 1-в-1
- **PGO + флаги применяются автоматически**
- **Гибридная память** (стек / malloc / mmap)
- **Валидаторы + sandbox + самопроверка**

## Что НЕ работает

- **ASM ARM / ASM x86** — только строки (нет runtime для чисел)
- **Sh классы** — нет ООП в bash
- **HTML** — только вывод строк
- **x86 на ARM** — не компилируется (нужен x86-ПК)
