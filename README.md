# SMA++ <GMA Compiler>

**SMA++** — это ультра-быстрый язык программирования с закрытым исходным кодом (Closed Source), созданный для эры автоматизации и шифрования, при этом без потерь в производительности и безопасности памяти 

---

## ⚡ Ключевые особенности

1. **Скорость на уровне Ассемблера (Runtime > Всё):** Благодаря собственному бэкенду MLS, код компилируется напрямую в x86-64 подобный ассемблер, минуя стандартные библиотеки Си.
2. **Абсолютная безопасность («Матрешка»):** Встроенная обфускация, шифрование строк (XOR), защита от отладчиков (Anti-Debug) и механизмы самоуничтожения (Kill-Switch).
3. **Минимум букв:** 1 строка на SMA++ заменяет 2-4 строк на C/C++. Нет лишних скобок, точек с запятой и сложных типов.
4. **Авто-типы и авто-память:** GMA компилятор сам решает, какой тип данных использовать (`uint8`, `int64`) и как выделить память (стек, куча, mmap).

---

## 🛠 Архитектура проекта

*   `smapp.py` — Интерпретатор и REPL для быстрого прототипирования.
*   `cma7.py` — Главный драйвер (GMA), компилирующий код в 13 языков.
*   `sma/lex.py` — Парсер и валидаторы (статический анализ).
*   `sma/gen_*.py` — Классические бэкенды (C, C++, Rust, Python, Go, Java и др.).
*   `sma/mls/backend_x86.py` — **Собственный бэкенд MLS**. Генерирует обфусцированный ассемблер x86-64 (syscalls, без libc).

## 🚀 Быстрый старт

### 1. Интерпретатор (REPL)
Идеально для тестирования логики и скриптов:

bash
python3 smapp.py examples/account_reg.sma


2. Компиляция в машинный код (MLS,Backend)

Собственная генерация ассемблера без использования Clang;

bash
python3 cma7.py hello_mls.sma out --backend=mls --run


3. Классическая компиляция (13 языков)

Генерация кода в C, Rust, Python и другие.

## 🛡 Безопасность («LARP»)

Компилятор GMA (через бэкенд MLS) закладывает в бинарник несколько уровней защиты:

1. Anti-Static: Junk Code (мусорные инструкции), рандомизация меток, шифрование строк через XOR.
2. Kill-Switch: Программа затирает полностью себя в RAM и на диске, делая реверс-инжиниринг невозможным.
3. FS (Final Stage): В будущих итерациях — сборка кода в памяти с полным удалением следов.

Примечание: Для отладки самого компилятора используйте интерпретатор smapp.py или флаг --debug (в разработке).
